# HC-2 deterministic core implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. James explicitly requested one agent and one commit for HC-2.

**Goal:** Independently testable, playable standard 2v2 matches with atomic commands and exact deterministic replay.

**Architecture:** Plain serializable TypeScript state. Commands validate and transition a clone; events describe all resolution. RNG is part of state. Replay stores config, rules version, seed and accepted commands.

**Tech stack:** TypeScript, Node, Vitest. No game-engine dependency.

**Spec:** ../specs/2026-11-24-core-rules-design.md and ../../../blood_bowl_hardwood_carnage_nba_jam_prd.md. Missing-rule implementation waits for James's explicit approval of the proposed design.

## Global constraints

- 15×26 court; exact four PRD duos and skills; one Blitz per team turn; four-turn possession clock.
- No unapproved rules defaults. Preserve full ruleset/config in replay. Illegal commands consume no RNG and mutate nothing.
- No milestone 2 aerial/fire/swarm implementation; keep those PRD requirements documented.
- No push, merge or PR. One commit starting HC-2, then board acceptance, proof and review status.

## Review focus

- Untrusted JSON commands: missing fields, wrong primitive types, nonfinite coordinates and unknown discriminants reject atomically.
- Pending dice choices: wrong chooser and unrelated commands reject, with no duplicated injury or RNG.
- Disabled players: crowd, KO, stunned, half recovery and no eligible receiver preserve valid ball ownership.
- Clock boundaries: shots, changed possession, half transition and final turn do not double-count or create extra turns.
- Replay save/load: malformed config, unsupported versions and rejected commands cannot yield plausible but incorrect history.

## File responsibilities and interfaces

- package.json, lockfile, tsconfig.json, .gitignore: reproducible install, strict typecheck, targeted test and headless runner scripts.
- packages/core/src/types.ts: config, teams, players, state, commands, events, pending rolls and replay types; ruleset version.
- court.ts: inBounds, distance, paint, rim, scoring zone and push candidates.
- dice.ts: serializable seeded generator, D6, 2D6, block faces and ST dice count.
- match.ts: exact roster templates, config validation, createMatch(config, seed), turn and half progression.
- commands.ts: legalActions(state, playerId), applyCommand(state, command), validation and action resolution.
- replay.ts: serializeReplay(replay), replayMatch(replay), runtime validation and event reconstruction.
- index.ts: public exports; runner.ts: complete scripted match and replay verification.
- packages/core/tests/{court,dice,match,commands,replay}.test.ts: focused behavior and contract fixtures.
- README.md: run commands, API contract, approved design link and limitations.
